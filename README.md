## 这是什么

一局游戏的形态是这样的：

> **玩家 A 的屏幕**：你是个走南闯北的行商，雨夜里在驿道上赶路。山道边倒着一个人，浑身是伤。他身上的军服，和你上周在城里见过的一批被通缉的人很像。
>
> **玩家 B 的屏幕**：你遭到伏击，跌落山崖。醒来时肋骨像是断了几根。一个牵着驮马的行商停在十步开外，正打量你，没有下马。

两人**同时在玩同一件事，看到的却完全不同**。双方各自行动，异步推进（像互相寄信，不是对战）。

**核心不是打赢，是判断。**

- 对方的"救我，我给你双倍的钱"是真话还是缓兵之计？
- 你填给系统的"真实打算"，会不会被对方看穿？
- 你身边这个"重伤的人"，到底是玩家还是 AI 扮的？

一局结束后双方可以选择**揭面**——看到对方的真实形象和穿搭。

**收费点**：外观（捏脸 + 穿搭），游戏币购买。**绝不 pay-to-win。**

## 为什么值得做

市面上 AI 游戏大多在做两件事：无限聊天（AI Dungeon 类）或单人跑团（AI DM 类）。这个项目赌的是另一件事：

### 1. 不对称信息本身就是玩法

大多数 AI 游戏的"对手"是环境或 NPC。这里的对手是**另一个信息不全的人**。AI 负责的不是"生成剧情"，而是**充当信息中介**——把 A 的表演翻译成 B 视角里能看到的东西，且不能漏、不能编、不能偏心。

这是 AI 在游戏里一个很少被探索的位置：**不是作者，是裁判的助手和翻译。**

### 2. 匿名对位解决了很多硬问题

| 问题 | 匿名异步怎么解决 |
|---|---|
| LLM 延迟 2~5 秒破坏节奏 | 异步下 30 秒甚至几小时都行 |
| 实时同步的工程复杂度 | 退化成「信封式回合」，一次只有一方行动 |
| 新游戏冷启动没人匹配 | **AI 兜底扮演**，永不空转，玩家无感 |
| 被打爆的心理压力 | 匿名 + 敌我难辨，压力大降 |

### 3. 异步让 3D 从"不可能"变成"可行"

这是个关键洞察，详见 [3D 角色方案](#3d-角色方案)。实时 3D + LLM 叙事在延迟和成本上走不通；但**异步 + 本地渲染**完全可行。

### 4. 复玩性不靠内容量，靠对位组合

5 个副本轮换，配上"不同玩家 × 不同表演"，就能撑很久。不需要每周产新内容。

## 现在能跑什么

不需要 LLM、不需要联网、不需要装依赖（Python 3.9+）：

```bash
git clone <this-repo> && cd ai-infinite-game/m0-prototype

python3 m0.py --play --solo      # 玩一局（雨夜驿道）
# 悬疑副本通过 agent 模式进入：--script ln-manor-01
python3 m0.py --redteam          # 三通道泄露测试
python3 m0.py --matrix           # intent 联动机制测试
python3 m0.py --guardtest        # 输出质量闸门测试
python3 m0.py --selftest         # 状态机自检
```

接真实 LLM（可选，不接也能跑）：

```bash
cp .env.example .env    # 填入你自己的 key
```

**M0 真实验证过的**（都有可复现输出）：

- 三通道隔离：未授权的 `intent` 原文 **0 次**出现在对方视图
- intent 联动：线索 = 「对方填了 intent」且「我方观察成功」，2×2 矩阵全对
- 状态机 10 回合无卡死
- 真实 LLM 端到端 8 回合：8.4s/次、287 completion_tokens/次
- 见 [DEVLOG](docs/DEVLOG.md)

## 核心机制：三通道双盲

这是整个设计的支点。

每个玩家提交一次行动时，可以填两样东西：

| 通道 | 玩家填什么 | 谁能看到 |
|---|---|---|
| **表演** Performance | 你实际说/做的事 | 对方 + 裁判 |
| **内心** Intent | 你真实的打算（可选） | **只有裁判，永不进对方侧** |
| **裁决** Judge | 系统产出的结构化结果 | 双方各自投影 |

### 为什么「内心」这一栏有意思

如果 intent 永不外泄，玩家为什么要填它？

**因为它能被识破。**

- A 填了"我打算等他伤好就抢他"
- B 如果洞察判定成功，裁判会把这段作为 B 的叙事素材
- B 看到："你注意到他握手时，目光一直停在你腰间的钱袋上"

于是有三层博弈：

| 层 | 玩家行为 |
|---|---|
| 第一层 | 只点预设选项的新手 |
| 第二层 | 自由描述表演的老手 |
| **第三层** | **填 intent 下注**——填真的可能被识破；**填假的就是主动钓鱼**，骗对手的洞察判定 |

关键：**系统无法验证 intent 真假**（AI 读不了心）。所以 intent 从来不是"事实"，只是"玩家自愿提交的叙事素材"。

这不是缺陷，这就是玩法。假 intent 是高级心理战。

### 隔离靠代码，不靠提示词

```python
# 铁律：构建对方视图的函数，签名里根本没有 Intent
def build_opponent_view(enc, viewer, up_to_turn) -> dict:
    ...
```

靠提示词说"不要说出去"是防不住的。**靠函数签名。** `--redteam` 会反射检查这个签名。

### 判定绝不给 LLM

骰子是确定性的，可复现、可回放：

```python
roll = HMAC_SHA256(seed, f"{encId}:{turn}:{actor}:{actionType}") % 20 + 1
```

原因很实际：**PvP 场景下 AI 一旦判"你失败了"，对手立刻获益，而玩家会认定 AI 在帮对面。这个指控无法自证清白**——LLM 输出不可复现、不可审计。

所以我们给玩家摊开明账：

```
掷骰 17   DC 15   加值 +1（天赋：夜行者）  →  成功
```

玩家可以不接受运气，但必须能接受明账。

## 架构

```
┌──────────────────────────────────────────────┐
│ L3 元层：账号 / 外观 / 游戏币 / 揭面 / 创作者   │
├──────────────────────────────────────────────┤
│ L2.5 Encounter：匿名对位 FSM + 三通道 + 超时   │
├──────────────────────────────────────────────┤
│ L2 AI 叙事层：意图解析 / 叙事渲染 / NPC 兜底    │  ← AI 只活在这里
├──────────────────────────────────────────────┤
│ L1 规则引擎：判定 / 状态机 / 结算 / 可见性投影  │  ← 纯代码，零 LLM
├──────────────────────────────────────────────┤
│ L0 世界种子：副本定义 / 规则集 / 物品白名单     │
└──────────────────────────────────────────────┘
```

**L1 是唯一真相源。L2 是可丢弃的渲染层。**
LLM 挂了、超时了、返回垃圾了，游戏必须能继续跑。

AI 在整条链路里只出现两次：**自然语言 → 结构化意图**，**结构化结果 → 自然语言**。判定 100% 在代码里。

## 3D 角色方案

> 详见 [docs/3d-avatar.md](docs/3d-avatar.md)

**核心判断：不是先做 3D 再做游戏，而是让 3D 成为叙事层的第二个输出。**

服务端只多输出一个字段：

```json
{
  "text": "雨点砸在脸上，你勉强睁开眼。",
  "emotion": "fear",
  "intensity": 0.7
}
```

客户端拿这个 + TTS 音频，用 `three.js` + `three-vrm` 实时驱动角色表情和口型。**不需要预渲染视频**，延迟接近零。

### 为什么这条路走得通

1. **VRM 1.0 有标准表情系统** —— `happy / angry / sad / relaxed / surprised / blink` + 五个元音口型 `aa / ih / ou / ee / oh`（[官方文档](https://vrm.dev/en/vrm1/expression/)）。情感标签直接映射，TTS 音频直接驱动口型。
2. **VRoid Studio 免费且可商用** —— 捏脸生态已成熟，正好是收费点（[商用许可](https://vroid.com/en/studio/guidelines)）。
3. **已有现成驱动轮子** —— 例如 [ARPAHLS/avatar](https://github.com/ARPAHLS/avatar)（VRM + LLM + lipsync + 浏览器）、[kajidog/mcp-vrm-player](https://github.com/kajidog/mcp-vrm-player)。**不用从零造。**
4. **异步容忍度** —— 实在要做重度演出，可以离线渲染，玩家下次回来再看。但建议先用客户端实时渲染，成本几乎为零。

所以"真实人物建模 + 表情 + 思考方式"这条，**不是幻想，缺的是一个人**。

## 诚实清单

**已实测的坏消息**（不是猜测，是跑出来的）：

- **MiniMax-M2 的内置安全审核不能当审核用**。实测三个暴力场景，`output_sensitive` 字段**全部返回 False**，但模型拒答了一次；拒答伪装成正常响应（`content = "我无法创作这个内容。"`）。同一批测试里，扎腿逼供被拒、割喉反而通过——**拦截毫无规律**。且它会悄悄把血腥描写软化成留白体。→ 内容策略必须自建，见 `output_issue()`。
- **M2.x 关不掉思维链**。`enable_thinking=false` 会被忽略（[证据](https://github.com/openclaw/openclaw/issues/122598)），必须用 `reasoning_split: true`，否则 `<think>` 块直接污染玩家看到的叙事。

**未验证的**：

- **好不好玩** —— 这是唯一的真问题，只有真玩才知道
- AI 兜底扮演的真实感（当前是写死的 mock）
- 规模化的成本（单局便宜，但并发和 UGC 审核成本未知）
- Steam 上"AI 标签"的市场影响（有研究称仅提及 AI 就掉 40~60% 销量，口径存疑，需自行核实）

**已知 P0 缺陷**：

- 叙事可以用状态暗示不存在的结果。实测中观察判定失败，叙事却写成"商人驱马走了"，但状态里人还在。修法：叙事事件白名单，narrator 不得描述规则引擎未产生的结果。
