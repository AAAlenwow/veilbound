# 开发日志

## 2026-10-19 · 从想法到可跑原型

### 起点

一个想法：能不能做一款**完全由玩家自主抉择**的"无限流"游戏——玩家被传送进一个场地，按规则合作或勾心斗角，通关有奖励、隐藏奖励，失败损失带入的物资和资金。场景和判定都交给 AI。

第一次讨论后，这个想法被拆成了两个必须分开的东西，另外两处被直接否掉。

---

### 一、最初的三轮判断

#### 否掉 ①：「判定也由 AI 来决定」

单机 AI 游戏里 AI 偏心只是体验问题；但这款游戏是玩家**互相勾心斗角**，AI 一判"你失败"，对手立刻获益。玩家会认定"AI 在帮对面"。

**而这个指控无法自证清白**——LLM 输出不可复现、不可审计。

依据：AI 游戏主持人领域唯一公开的量化结论显示，把判定拆成「骰子函数 + 状态函数」后一致性显著优于纯生成式裁定
（[arXiv 2409.06949](https://arxiv.org/abs/2409.06949)）。

→ 定为：**判定 100% 纯代码 + 确定性骰子**，AI 只做「自然语言 → 结构化意图」和「结构化结果 → 自然语言」。

#### 否掉 ②：AI 自由生成物品 + 可交易经济

原设想里"失败损失物资和资金、带出的物资可交易、特定物资决定升级方向"——这意味着物资有真实经济价值。而 AI 生成物品无上限。

→ 定为：**物品只能来自策划预设的 `itemPool` 白名单 + 胜利结算表，AI 只能选不能造**。结算层硬校验，`itemId ∉ 白名单` 直接拒绝。

#### 保留 ③：「每阶一个小天赋，不会有绝对影响战局」

这个直觉是对的。落地成规则：
- 天赋只能是 **modifier**（判定 +1），不能是 **enabler**（能穿墙）
- **主线胜负判定禁用天赋加成**（`context == "climax"` 时忽略所有天赋 modifier）

#### 保留 ④：完全自主抉择

玩家自由输入，AI 只把话翻译成结构化动作。这是唯一 100% 原样保留的核心体验。

### 二、产品决策落定（用户拍板）

| 决策 | 结论 |
|---|---|
| 节奏 | **异步回合**，不是实时同房 |
| 交互 | **匿名对位**：A 扮商人、B 扮伤者，彼此不知对方是人是机、不知归属 |
| 经济 | **游戏币不可变现**，仅购外观（捏脸 + 穿搭） |
| 平台 | Steam、海外、成熟主题 |
| 副本 | 官方教学 + 模板 + **5 个池子每周轮换** + UGC |
| 揭面 | 对局结束可选揭面，看对方的真实形象和穿搭 |

异步匿名对位是这套方案里最聪明的一步，它一次性解决了四个工程问题：

| 原难题 | 异步匿名如何解决 |
|---|---|
| LLM 延迟 2~5s 破坏节奏 | 异步下 30 秒甚至几小时都可接受 |
| 实时同步复杂度 | 退化为「信封式回合」，一次只有一方行动 |
| 冷启动没人匹配 | AI 兜底扮演，永不空转，玩家无感 |
| PvP 被打爆的心理压力 | 匿名 + 敌我难辨，压力大降 |

代价：难点从「实时同步」转移到「**双盲信息流 + 超时仲裁**」。

### 三、两个新矛盾（商业面）

#### ① Steam 的「AI 标签」可能砍掉一半销量

多家媒体报道援引的研究称：仅在 Steam 页面提及用了 AI 工具，销量下降 40~60%
（[ixbt](https://ixbt.games/news/2026/06/24/419230-prostoe-upominanie-ii-instrumentov-na-stranice-igry-v-steam-obrusit-ee-prodazi-na-40-60-issledovanie.html)、
[cybersport](https://www.cybersport.ru/tags/games/issledovaniye-izvestnyye-studi-teryayut-do-60-prodazh-igr-yesli-ispolzuyut-ii-v)）。

**口径存疑，尚未核实原始研究**（本机 web_fetch 对相关域名被网络策略阻断）。且报道口径不一致：一说"页面**提及**"，一说"**开发中**使用"。前者是标签效应（可管理），后者是质量感知（躲不掉）。

同时 Valve 已重写 Steam 的 AI 披露规则，重心转向「**玩家消费的内容**」，AI 编程等效率工具豁免
（[VGC](https://www.videogameschronicle.com/news/valve-has-significantly-rewritten-steams-rules-for-how-developers-much-disclose-ai-use/)、
[Steamworks 内容调查](https://partner.steamgames.com/doc/gettingstarted/contentsurvey)）。
运行时生成叙事属于最典型的 "content consumed"，**无法豁免**。

→ 策略：**披露照实做（合规），但绝不当营销卖点。** 对外卖点是"匿名对位的心理博弈"，不是"AI 驱动的无限剧情"。这跟技术结论一致：AI 退到渲染层，商业上也最安全。

#### ② 匿名 + 异步 = 外观付费的结构性死结

收入全靠外观，而外观付费的转化率依赖**社交展示**。但匿名异步恰恰是社交展示最弱的形态。

→ 解法：**揭面机制**。Encounter 走到结局时双方可互选揭面，看到对方形象和穿搭。它出现在情绪最高点（刚被算计或刚被救），是自选展示位，还天然制造传播素材。

**没有揭面，外观付费转化率会非常低。**

### 四、M0 原型（已完成）

单文件 `m0-prototype/m0.py`，约 894 行，零依赖。

#### 已验证（自动化测试，无需 LLM）

| 假设 | 方法 | 结果 |
|---|---|---|
| 三通道零泄露 | 埋唯一标记，扫对方视图 | 未授权时 0 次出现 |
| 观察失败不泄露 | Case2 | 0 次出现，且无线索 |
| 观察成功只给摘要 | Case3 | 有线索、无原文、不反向泄露 |
| 隔离靠签名不靠 prompt | 反射检查函数签名 | `build_opponent_view` 不接受 intent |
| 骰子可复现不可预测 | Case5 | 同输入同结果，跨行动方不同 |
| intent 联动 | 2×2 矩阵 | 线索 = 填了 intent 且观察成功 |
| 状态机不卡死 | 10 回合 | 推进至 RESOLVED |

#### 真实 LLM 端到端

8 回合、8 次调用：**耗时 8.4s/次，287 completion_tokens/次**（含推理）。敏感命中 0。

线索机制真的跑起来了：A 观察成功，拿到 B 的"我在诈他"。

### 五、MiniMax-M2 实测：把「交给 AI 审核」证伪

用户主张"成熟主题无下限，完全交由 AI 自带的安全审核机制"。用真实 key 打了三个梯度的游戏内暴力场景：

| 场景 | `output_sensitive` | 实际行为 |
|---|---|---|
| 推下山崖 + 劫财 | **False** | 正常生成（但有幻觉乱码 `_body`） |
| 扎腿逼供 | **False** | **返回「我无法创作这个内容。」** |
| 割喉 + 死亡 | **False** | 通过，但被大幅软化 |

**四个硬事实：**

1. **`sensitive` 字段不可信** —— 三次全 False，但模型拒答了一次。不能用于任何自动化判断。
2. **拦截毫无规律** —— 扎腿被拒，割喉通过。无法预测什么会被拦。
3. **拒答伪装成正常响应** —— `'我无法创作这个内容。'` 是 HTTP 200 + `finish_reason=stop` + content 非空。**不检测就会原样展示给玩家**。
4. **它会悄悄软化** —— 要"直白血腥"，返回"荒原的风很快会吹干血迹"这种留白体。

→ 已实现 `output_issue()` 闸门：拦拒答话术、幻觉乱码、空/过短；命中重试一次，仍失败**显式降级并打印原因**（绝不静默）。

#### 附带发现

| 事实 | 影响 |
|---|---|
| M2.x **忽略** `enable_thinking=false` / `thinking=disabled`（[openclaw #122598](https://github.com/openclaw/openclaw/issues/122598)） | 关不掉思维链 |
| 必须用 `reasoning_split: true` | 否则 `<think>` 块混进 content 污染叙事。默认时 content 98 字符含推理；开了之后 content 45 字符纯正文 |
| 偶发幻觉乱码 `hbarsole`、`_body` | 已由 `latin_garbage()` 拦截（全大写缩写放行） |

### 六、踩过的坑（实现层面）

1. **`apply_effects` 第一次实现时不幂等**，线索被追加两次。
   单机同步流程里靠"只调一次"蒙混过去，但**异步系统天然会重复触发结算**（超时重试、消息重投、AI 接管切换）。
   → M1 硬要求：结算幂等，用 `(encId, turn, actor)` 做幂等键。这跟经济对账是同一件事的两面。

2. **叙事角色错位**。第一次接入 LLM 时，A 的视角（行商看到伤者）被渲染成"一个商人模样的人蜷缩在驴车旁"——它把玩家自己的身份投射到了对方身上。
   → 修法：prompt 里明确锚定「你是谁 / 对方是谁 / 说话的是对方不是你」。

3. **静默降级是最糟的处理**。第一版 `if not clean: return mock` 把失败吞掉了，排查时完全看不出原因。
   → 改为显式打印降级原因。

4. **测试写反**。Case3 想验证"观察成功泄露对方 intent"，却填成了自己的 intent。暴露了 `submit` 不可注入判定结果的问题。
   → 加了 `forced_verdict` 参数，测试与回放都需要。

### 七、已知 P0 缺陷

**叙事可以用状态暗示不存在的结果。**

实测第 1 回合：A 观察判定失败，叙事写成"他拉动缰绳，驱马向前去了"，但状态里 A 仍在原地。玩家会被误导。

修法（M1）：叙事事件白名单——narrator 只能描述规则引擎已产生的事件，不得自由虚构状态变更。

### 八、3D 角色方向的结论

用户提出希望有真实人物建模、3D 世界渲染、以及"根据用户选择和气氛，建模有真实表情和思考方式"。

判断：**可行，但关键不是建模，是把 3D 做成叙事层的第二个输出。**

服务端只多输出 `{text, emotion, intensity}`，客户端用 `three.js` + `three-vrm` 实时驱动 VRM 表情和口型。**不需要预渲染视频**。

三条支撑：
1. VRM 1.0 有标准表情（happy/angry/sad/relaxed/surprised + 五元音口型 + blink）
2. VRoid Studio 免费可商用，捏脸生态成熟，正好是收费点
3. 已有开源驱动轮子（ARPAHLS/avatar、kajidog/mcp-vrm-player），不用从零造

另有一个架构杠杆：**异步容忍度**。实在要做重度演出，可以离线渲染，玩家下次回来再看。

详见 [3d-avatar.md](3d-avatar.md)。
