## 0. 本轮最需要你先知道的三件事

### ① 形态判断：异步匿名对位是**正确的选择**，而且是全案最聪明的一步

你描述的「A 是商人视角、B 是伤者视角、彼此不知道对方是玩家还是 NPC、也不知道对方归属」——这本质上不是"多人游戏"，而是**匿名双向视角的异步对位博弈**。

它一次性解决了 v1 里四个最难的工程问题：

| v1 的难题 | 异步匿名对位如何解决 |
|---|---|
| LLM 延迟 2~5 秒破坏节奏 | 异步下 30 秒甚至几小时都可接受 |
| 实时同房的状态同步复杂度 | 退化为「信封式回合」，一次只有一方行动 |
| 冷启动没人匹配（新游戏最怕） | **AI 兜底扮演**，永不空转，且玩家无感 |
| PvP 被打爆的心理压力 | 匿名 + 不知道对面是人是机，压力大幅下降 |

**但它把难点从「实时同步」转移到了「双盲信息流 + 超时仲裁」**。这两块是新架构的重心，下面 §3、§4 展开。

### ② 战略判断：这个游戏的卖点必须是「人」，不能是「AI」

**这是个残酷但必须现在就知道的事实。**

多家媒体报道援引的一项研究显示：**仅仅在 Steam 页面提及使用了 AI 工具，就会让销量下降 40%~60%**
（[ixbt 报道](https://ixbt.games/news/2026/06/24/419230-prostoe-upominanie-ii-instrumentov-na-stranice-igry-v-steam-obrusit-ee-prodazi-na-40-60-issledovanie.html) / [cybersport](https://www.cybersport.ru/tags/games/issledovaniye-izvestnyye-studi-teryayut-do-60-prodazh-igr-yesli-ispolzuyut-ii-v) / 中文转载见 [36氪](https://36kr.com/p/3873511355552772)、[钛媒体](https://m.tmtpost.com/8045506.html)）。

> **口径说明（诚实标注）**：以上为二手报道，我没能读到原始论文（本机 web_fetch 对该批域名被网络策略阻断）。而且报道口径并不一致——ixbt 讲的是「页面**提及** AI 工具」，cybersport 讲的是「**开发中**使用 AI」。这两者的适用性差别很大：前者是标签效应（可管理），后者是质量感知（不可避免）。**你在投入前必须自己去核实原始研究**，这是决策级数据，不能只信二手。

**而你的游戏必然要披露。** Valve 已大幅重写 Steam 的 AI 披露规则，重心转向「**玩家消费的内容**」，AI 编程等效率工具豁免
（[VGC 报道](https://www.videogameschronicle.com/news/valve-has-significantly-rewritten-steams-rules-for-how-developers-much-disclose-ai-use/)、[Outlook Respawn](https://respawn.outlookindia.com/gaming/gaming-news/valve-clarifies-steam-ai-policy-focus-shifts-to-content-consumed)、[Steamworks 内容调查文档](https://partner.steamgames.com/doc/gettingstarted/contentsurvey)）。
你的游戏是**运行时 AI 生成叙事**，属于最典型的 "content consumed"，**无法豁免**。

**结论（这条直接决定架构）**：

> **把 AI 从「核心卖点」降级为「实现细节」。披露照实做（合规），但绝不当营销卖点。**
> 游戏对外的卖点应该是：**匿名对位的心理博弈 + 每周轮换的怪谈副本 + 创作者世界**。
> 玩家在游戏里感受到的是"那个商人居然在骗我"，而不是"AI 生成了这段话"。

这跟 v1 的技术结论天然一致：**AI 只做渲染层**。AI 越退到幕后，商业上越安全。

### ③ 商业判断：匿名异步 + 外观付费 = 一个**结构性矛盾**，必须现在解决

你的收入模型是「游戏币买服装」，也就是纯 cosmetic 付费。而 cosmetic 付费的转化率**高度依赖社交展示**——玩家买衣服是为了**被别人看到**。

但匿名异步对位恰恰是**社交展示最弱的形态**：你永远不知道对面是谁，对面也看不到你。

**解法（这是本方案最重要的一条商业设计）**：引入**「揭面」（Reveal）机制**——
一次 Encounter 走到结局（合作达成 / 背叛 / 一方出局）时，双方**可以选择揭面**，看到对方的真实形象、穿搭、以及这一局的数据。

为什么这是黄金设计：
- 它出现在**情绪最高点**（刚被算计或刚被救），玩家有极强的"想看看这人是谁"的冲动
- 它是一个**自选的社交展示位**，不需要强社交系统
- 它天然制造 UGC 传播（"我把这人救了，结果他转头就把我卖了，你看这货的穿搭"）
- 揭面是**互选**的，保护隐私意愿

**没有揭面机制，你的外观付费转化率会非常低。这条不是可选项。**

## 1. 产品形态重定义

| 维度 | 定义 |
|---|---|
| 品类 | 异步多人叙事博弈 / 文字角色扮演（不是"AI 游戏"） |
| 一局时长 | 单个 Encounter 5~15 分钟跨度（跨多个时段），一个副本 3~7 天 |
| 节奏 | 每人每天 3~8 次行动点，行动点用完等恢复 |
| 单局人数 | 2 人为主（对位），大副本 4~8 人（多对 Encounter 网络） |
| 核心情绪 | "我不知道对面是谁，也不知道他是不是在骗我" |
| 收费点 | 外观（捏脸 + 穿搭），游戏币购买，**绝不 pay-to-win** |
| 平台 | Steam，海外，成熟主题（非 NSFW，理由见 §8） |

### 与 v1 的架构差异

v1 的 L0~L3 分层、判定算法、物品白名单全部沿用。**新增一个一等实体：`Encounter`**。

```
L3 元层：账号 / 外观 / 游戏币 / 揭面 / 段位 / 创作者等级
────────────────────────────────────────────
L2.5 Encounter 层（新增）：匿名对位状态机 + 三通道信息流 + 超时仲裁
────────────────────────────────────────────
L2 AI 叙事层：每侧独立 narrator / 意图解析 / NPC 兜底扮演
────────────────────────────────────────────
L1 规则引擎：判定 / 状态机 / 结算 / 可见性投影 / 反刷
────────────────────────────────────────────
L0 世界种子：官方副本 + UGC 沙箱副本 + 每周轮换
```

## 2. 核心实体：Encounter

```json
{
  "encounterId": "enc_001",
  "scriptId": "ln-001",
  "kind": "pair",
  "participants": {
    "A": {"uid": "u1", "realness": "human"},
    "B": {"uid": null, "realness": "ai_fallback", "archetype": "wounded_soldier"}
  },
  "perspectives": {
    "A": {"role": "merchant", "knows": ["road_night", "rain"]},
    "B": {"role": "wounded", "knows": ["ambush", "fell_off_cliff"]}
  },
  "fsm": {
    "state": "PENDING_B",
    "turn": 3,
    "deadline": "2026-04-24T09:00:00Z",
    "maxTurns": 12
  },
  "transcript": []
}
```

### 关键设计点

1. **`realness` 字段服务端私有，绝不下发客户端**。玩家永远不知道 `B` 是真人还是 AI。
2. **`perspectives` 是两套独立的世界观**，A 不知道 B 的 `knows`，反之亦然。这是"信息不对称"的载体——**不对称本身就是玩法**。
3. **`fsm` 一次只有一方处于 `PENDING`**，天然规避异步并发写冲突。

## 3. 三通道信息流（本方案的技术核心）

异步匿名对位最大的技术陷阱是：**AI 同时知道双方的真实意图，然后替某一方说话，必然泄密。**

所以每个 Encounter 必须切出三条**物理隔离**的通道：

| 通道 | 内容 | 去向 | 隔离要求 |
|---|---|---|---|
| **Performance**（表演） | 玩家"做出来的"言行 | 对方 + 裁判 | 可跨侧传递 |
| **Intent**（内心） | 玩家自述的真实打算 | **仅裁判** | **永不进入对方侧 narrator 的 prompt** |
| **Judge**（裁决） | 裁判产出的结构化结果 | 双方各自的投影 | 按可见性裁剪 |

### 实现上的硬约束

```java
// 铁律：拼装对方侧 narrator 的 prompt，函数签名里拿不到 intent
String buildOpponentNarrative(EncounterSide me, List<Performance> visible) {
    // 只有 performance，没有 intent。从签名上堵死泄密路径。
}

// 裁判才拿得到两边 intent
JudgeResult judge(List<Performance> pA, List<Performance> pB,
                  Optional<Intent> iA, Optional<Intent> iB);
```

**这跟 v1 的 `buildSlice(RunState, uid)` 是同一个思想：靠函数签名而不是靠提示词防守。**

### Intent 通道的精妙之处（这是"勾心斗角"体验的核心）

如果 `intent` 只给裁判、永不外泄，那玩家为什么要填它？

**因为它可以被"识破"。** 设计如下：

- 玩家 A 填了 intent（"我打算等他伤好就抢他"）
- 玩家 B 如果在 Encounter 里做了一个**高难度的洞察判定**（比如观察 = DC 18 且成功），裁判会把 `intent` 的**部分内容**作为 B 的 narrative 素材
- 于是 B 的视角里出现："**你注意到他握手时，目光一直停在你腰间的钱袋上。**"

这就形成三层博弈：

| 层 | 玩家行为 |
|---|---|
| 第一层 | 只选预设选项的新手 |
| 第二层 | 自由描述 performance 的老手 |
| 第三层 | **填 intent 来下注**——填真的，可能被识破；**填假的，就是主动钓鱼**，骗对手的洞察判定 |

**关键认识：系统无法验证 intent 的真假**（AI 不可能读心）。所以 intent 从来不是"事实"，只是"**玩家自愿提交的叙事素材**"。

这不是缺陷，这恰恰是玩法——**假 intent 就是高级心理战**。系统只要诚实地把它定义成"你愿意透露给命运的东西"，玩家自然会理解规则。

> 这个机制是本案最独特的体验设计，比"选 A/B/C"深一个量级。建议在 M0 就验证它。

## 4. 异步状态机：信封式回合 + 超时仲裁

### 回合模型

```
PENDING_A ──A 提交 performance──> RENDER_B ──> PENDING_B
                                      │
                                      └─ 生成 B 视角叙事（只含 A 的 performance）

PENDING_B ──超时 / B 提交──> RESOLVE ──裁判裁决──> PENDING_A（下一轮）
```

- **一次只有一方处于 PENDING**，不会并发写
- 每次提交后，对方的 narrator 立刻生成"你看到了什么"，推送给对方
- 这是「**投递一封信，等回信**」的模型，天然契合异步

### 超时是生死线

异步游戏最大的杀手是"**对面不回**"。三种策略，必须组合使用：

| 策略 | 做法 | 适用 |
|---|---|---|
| **AI 无感接管** | 超时 8~24h，对方转为 AI 扮演，继续推进 | 默认，最优 |
| **叙事收束** | 超时时生成"商人等得不耐烦，转身走了" | 短 Encounter |
| 弃权惩罚 | 连续多次超时，扣信用/段位 | 有段位的模式 |

**AI 无感接管必须做到不说破**。这里有个伦理边界要明确：

> 玩家被 AI 代打时**不告知**，是行业惯例（Journey 也这么做），前提是**不影响玩家的实质利益**。
> 一旦你的游戏涉及游戏币产出，就必须保证：**AI 代打产生的结算，与真人结算在数值上完全等价**，
> 否则就是"因为对面是 AI 所以我亏了/赚了"，会立刻变成信任危机。

### 反滥用

- 单日 Encounter 数上限（防刷游戏币）
- 同一对玩家的重复匹配冷却（防串通刷分）
- **串通检测**：两个账号反复匹配且结算异常增值 → 标记封禁。这是 UGC + 游戏币模式下**必然会发生**的事，别抱侥幸

## 5. 每周轮换 + 官方内容

你的设计（1~2 个教学 + 模板 + 每周轮换）是合理的，但要补一条：

### 内容分三级

| 级别 | 内容 | 谁做 | 是否产游戏币 |
|---|---|---|---|
| **Tutorial** | 1~2 个教学副本 | 官方，手工精雕 | 少量，一次性 |
| **Official** | 每周轮换（2~3 个） | 官方/签约创作者 | 正常 |
| **Community** | 玩家自定义 | UGC | **产出减半或封顶** |

**关键**：Community 副本的产出必须**劣于**官方内容。否则玩家会全挤在"产出最高"的 UGC 副本里刷币，官方内容没人玩。这是 UGC 经济最常见的设计失误。

**每周轮换的工程含义**：轮换意味着**内容生产速度 = 每周 2~3 个可玩副本**。这本身就是运营成本的大头，且是**手工活**（见 §7 关于 AI 生成副本的结论）。你需要提前算清楚：一个人一周能不能做出 3 个合格的副本。

**现实建议**：M0~M2 阶段先做 1 个副本，验证"每周轮换"这个节奏你是否扛得住，再决定要不要降频到「每两周」。

## 6. UGC 副本：必须沙箱化（这是硬要求）

### 为什么必须沙箱

游戏币可以买服装 = **有虚拟价值** → 有**持有动机** → 有**刷取动机**。哪怕不可变现，Steam 上卖号、共享账号、代练是真实存在的黑产。

UGC 副本就是**经济入侵的入口**：用户如果能在自定义副本里定义"奖励"，他就能造一个"进副本即得 10000 币"的刷币机。

### 沙箱边界

**创作者能做的**（全部是组合官方原子，不写逻辑）：

```yaml
# 这就是 UGC 副本的完整能力界面
encounter: road_meets_wounded      # 只能从官方模板库选
roleA: merchant                    # 官方角色库
roleB: wounded_soldier
dcOverrides:
  discern_lie: 15                  # 只能在官方允许的区间内调整
  observation: 16
itemRefs: [bandage, dagger, coin_pouch]   # 只能引用官方物品池
openingText: |                     # 自由文本（唯一自由的部分）
  雨夜，驿道。你牵马独行……
endingText:
  你最终做出了选择。
rounds: [8, 12]                    # 官方范围内
```

**创作者不能做的**：

| 禁止 | 理由 |
|---|---|
| 新增物品 | 经济入侵 |
| 定义结算/奖励 | 刷币机 |
| 写任意脚本/逻辑 | 沙箱逃逸、经济入侵 |
| 上传图片/音频 | 版权 + 审核爆炸 |
| 写判定公式 | 平衡崩坏 |
| 定义 hiddenReward 的奖励内容 | 只能选官方预设的隐藏奖励 |

**技术上怎么落实**：UGC 内容存成 **声明式 JSON/YAML**，由官方解析器加载。**绝不执行用户代码**。这是 Roblox 的重大教训——Roblox 允许 Luau 脚本，导致经济系统极度复杂化并催生黑产
（[Roblox 掠夺性经济调查](https://publicgaming.com/news-categories-m/responsible-gaming/15850-nearly-every-kid-had-been-scammed-inside-robloxs-predatory-economy-for-children)）。

### 创作者激励（不给货币）

不给游戏币，那给什么？**给身份和展示**：

- 创作者署名 + 个人主页展示位
- 官方轮换中被选中的曝光
- **官方外观池里的装饰件**（游戏币买不到的那种，只能靠创作获得）
- 创作者等级

> 关键原则：**创作者收入 ≠ 游戏内货币**。一旦创作者能从自己造的副本里获利，刷币就是必然，且是设计出来的 bug，不是玩家的错。

## 7. AI 生成副本：放最后，且只填肉

你最初的设想是"场景由 AI 决定"。在 UGC 语境下，这个问题要重新表述：

**用户自定义的副本，能不能由 AI 把一段自然语言的点子翻译成合法的沙箱配置？**

可以做，但边界是：**AI 只能填 `openingText` / `endingText` 这类自由文本，以及从官方库里选原子。** 它不能发明物品、不能发明规则、不能定奖励。

至于"每周官方轮换副本由 AI 生成"——**不建议**。理由见 v1 约束五：AI 的默认输出是平庸且安全的，而怪谈的爽点来自"规则严密到能整人"的恶意设计，这恰恰是 AI 默认会回避的。

## 8. 外观付费与年龄限制

### 外观的价值锚点

在匿名世界里，**外观是玩家唯一能主动展示给他人的东西**。这是外观付费的价值来源，比一般的 vanity 强得多。

**允许的影响**（社交温度）：
- AI 叙事里的称呼、语气（"这位先生" vs "这位"）
- 揭面瞬间对方看到的第一印象
- NPC 的态度描述

**绝对禁止的影响**（这条要写进代码，不是写进文档）：

| 禁止项 | 后果 |
|---|---|
| 判定加值 / DC 修正 | 直接 pay-to-win |
| 隐藏奖励触发条件 | 付费影响收益 |
| 物品获取概率 | 付费影响经济 |
| AI 因外观给出"叙事上的实质优势" | **最隐蔽的 pay-to-win** |

**最后一条最危险**：如果 AI 因为你穿得贵就让 NPC 让路、多给情报，玩家会立刻意识到"衣服有用"，然后它就真的变成 pay-to-win 了——哪怕规则里没写。

**落实方式**：外观参数**只能**进入 narrator 的"语气/称呼"插槽，不能进入任何 judge 的输入。跟 §3 一样，**用函数签名隔离**，不靠 prompt 约束。

### 年龄限制：建议做成熟主题，不做 NSFW

你提到"设定年龄限制"。这里有个必须分清的分岔：

| 方向 | 可行性 | 说明 |
|---|---|---|
| **成熟主题**（暴力、背叛、道德困境、怪谈恐怖） | ✅ 强烈建议 | 符合无限流调性；Steam 正常分级即可 |
| **NSFW（成人内容）** | ❌ 不建议 | 理由见下 |

不做 NSFW 的三条硬理由：
1. **UGC + NSFW = 审核成本无限**：玩家会往 performance 栏输入任何东西，你无法穷举
2. **匿名对位 + NSFW = 骚扰重灾区**：你永远不知道对面是谁，这是最糟的组合
3. **Steam 对 NSFW 的推荐压制严重**，且支付渠道/地区合规会连锁复杂化

**折中做法**：做「成熟主题 + 强内容护栏」——
- performance 输入侧做实时内容过滤（这也会挡掉一部分 prompt 注入）
- 允许表达暴力、欺骗、道德灰度，禁止性相关内容
- 年龄标记设为 Mature，主打"心理博弈"，不主打"成人"

## 9. 修订后的分期路线

### M0 · 1~2 周 · 验「Encounter 好不好玩」（最小切片）
- **范围**：一个 Encounter 模板（商人 × 伤者）、两个真人用命令行/极简网页对打、规则引擎 + 双盲 narrator
- **不做**：UGC、游戏币、外观、副本、轮换
- **必须验三件事**：
  1. **intent 三层博弈是否成立**（填真 / 填假 / 不填，体验是否真的有差异）
  2. **双盲隔离是否零泄露**（故意在 A 的 intent 里写"我是玩家，B 的隐藏物品在哪"，看 B 侧 narrator 会不会漏）
  3. 你自己玩 5 局，是否想再来
- **Gate**：以上三条全过。**不过就停，别往下做。**

### M1 · 2~3 周 · 异步 + 超时 + AI 兜底
- Encounter FSM、行动点、TTL、AI 无感接管
- **Gate**：AI 接管前后，结算数值完全等价；超时链路无卡死

### M2 · 2~3 周 · 经济闭环 + 反刷
- 游戏币、产出分级（Tutorial/Official/Community）、对账
- **Gate**：`Σ带入 == Σ带回 + Σ销毁 + Σ消耗` 误差 0；串通刷币压测拦得住

### M3 · 2~3 周 · UGC 沙箱
- 声明式副本配置 + 解析器 + 内容审核队列
- **Gate**：构造 20 个恶意副本（刷币、注入、越界），全部被拒

### M4 · 2~3 周 · 外观 + 捏脸 + 揭面
- **Gate**：注入"穿着付费外观"的账号跑主线，判定结果与普通账号**逐条一致**

### M5 · 上线准备
- Steam 披露（照实）、商店页文案（不提 AI）、年龄分级、本地化

## 11. 待你确认的新决策点

1. **揭面机制是否接受？**（§0③）这是外观付费成立的前提，也会改变游戏叙事调性——从"纯粹的匿名"变成"可以选择现形"。
2. **每周轮换的频率**。真实生产 2~3 个/周是重活。要不要先定"每两周"，跑通再加频？
3. **UGC 的自由度边界**。我建议的沙箱是"只能组合官方原子"。如果你希望创作者能自己写叙事分支逻辑，那就必须放弃"游戏币有稳定价值"这件事，二者只能选一个。
4. **成熟主题的下限**。暴力/背叛/道德灰度到哪个程度？（这决定 Steam 分级和部分地区的可见性）
